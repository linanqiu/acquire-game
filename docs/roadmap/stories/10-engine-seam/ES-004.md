# ES-004: Calculator Pack

## Metadata
- **Epic**: [Engine Seam](../../epics/10-engine-seam.md)
- **Status**: `complete`
- **Priority**: `high`
- **Effort**: `M` (1-2h)
- **Dependencies**: ES-001

## Context

Arithmetic lives in code; judgment lives in the agent. The calculator pack is the set of exact
figures "a very precise human with a calculator" could derive from public information. Spec:
[seat-contract](../../../architecture/seat-contract.md), "Calculator pack".

## Requirements

`build_calculator_pack(game, viewer_id) -> dict`, pure and JSON-serialisable. Contains:

- per chain: size, price, safe flag, stock available;
- every player's public holdings and cash;
- majority/minority holders and the bonus payout for each chain if acquired now;
- the viewer's net worth, and every player's projected end-game score;
- remaining tiles in the bag (count only, not contents);
- only public info plus the viewer's own holdings and hand.

## Acceptance Criteria

- [x] Pure: does not mutate the game (state fingerprint compared before/after, for every viewer, every 40th action of every fuzzed game).
- [x] Bonus amounts equal what the engine actually pays on a real merger in the same state (test for ties and single-holder cases).
- [x] Prices and sizes match the engine's price table for every chain size.
- [x] No other player's hand or the bag order appears in the output (leak test over fuzzed games: no tile of another hand or of the bag appears in the JSON pack; self-test shows the check can fail).
- [x] JSON round-trips.

**Status note (2026-11-14):** `tests/test_calculator.py` checks packs against the engine over bot
games (payouts, projected scores, prices, merger outcomes) and JSON round trip. Purity and the
leak test now run inside the fuzz driver (`test_decisions.check_calculator_purity_and_leaks`).
`projected_rank` uses the same competition ranking as `Game.end_game` (ties share a rank).
