# ES-003: Snapshot / Restore

## Metadata
- **Epic**: [Engine Seam](../../epics/10-engine-seam.md)
- **Status**: `complete`
- **Priority**: `critical`
- **Effort**: `L` (2-4h)
- **Dependencies**: ES-002

## Context

Tier-3 screen tests (Epic 11) need to start at a specific game state without playing 30 turns, and
reconnect/restart handling benefits from the same capability. Spec:
[seat-contract](../../../architecture/seat-contract.md), `backend/game/snapshot.py`.

## Requirements

- `to_snapshot(game) -> dict` (JSON-serialisable, versioned) and `from_snapshot(data) -> Game`
  (raises `ValueError` on bad version/shape).
- Complete: RNG state, tile bag order, hands, board, chains, stocks, money, merger state, pending
  action, trades, events, `stocks_bought_this_turn`, turn order, current player.

## Acceptance Criteria

- [x] Property test: at every step of fuzzed full games, `from_snapshot(to_snapshot(g))` followed by the same action sequence gives identical states and events as continuing `g`.
- [x] Snapshot taken mid-merger, mid-disposition, with a pending trade, and in the buy phase restores correctly.
- [x] Snapshot survives `json.dumps`/`json.loads`.
- [x] Unknown `SNAPSHOT_VERSION` or malformed data raises `ValueError`, not a partial game.
- [x] Restored game has no references to the original (mutating one does not affect the other).

**Status note (2026-11-14):** verified against `backend/tests/test_snapshot.py` (fork-and-compare
property test over seeded bot games with phase-coverage check, merger/disposition/trade/buy-phase
round trips, JSON round trip, malformed-snapshot rejection, no-aliasing check, and attribute-list
guards that fail when a new `Game` attribute is not snapshotted).

## Verification

```bash
pytest backend/tests -q -k snapshot
```
