# ES-006: Test-Mode Endpoints

## Metadata
- **Epic**: [Engine Seam](../../epics/10-engine-seam.md)
- **Status**: `in-progress`
- **Priority**: `high`
- **Effort**: `M` (1-2h)
- **Dependencies**: ES-003, ES-005

## Context

Tier-3 screen tests start from snapshots and use scripted opponents
([Epic 11](../../epics/11-test-pyramid.md)). These need server endpoints that must not exist in
production. Spec: [seat-contract](../../../architecture/seat-contract.md), "Test-mode only".

## Requirements

- Enabled only when `ACQUIRE_TEST_MODE=1`.
- `POST /test/room/{code}/load-snapshot` with `{"snapshot", "seat_map"?}`: replaces the room's game
  with the restored one, maps snapshot player ids to room player ids, broadcasts state.
- `POST /room/{code}/add-seat` with `{"agent_id": "scripted", "script"?: [...]}`: scripted seat; no
  script means "play the first legal action". (Scripted seats themselves are built in TP-002.)
- When test mode is off, these routes return 404 and the `scripted` catalog id is not offered.
- Tier-4 journeys must not use these endpoints (enforced by TP-005).

## Acceptance Criteria

- [x] With test mode off: `/test/*` returns 404 and `add-seat` with `scripted` is rejected.
- [x] With test mode on: load a snapshot into a room with connected clients; clients receive the new state and the driver resumes if an agent seat is up next.
- [x] Bad snapshot returns 4xx and leaves the room's game untouched.
- [x] Deployment config (Dockerfile/Railway) never sets `ACQUIRE_TEST_MODE`; a test asserts the default is off.

## Verification

```bash
pytest backend/tests -q -k "test_mode"
```
