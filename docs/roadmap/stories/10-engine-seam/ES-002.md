# ES-002: Event Log (supersedes BL-004)

## Metadata
- **Epic**: [Engine Seam](../../epics/10-engine-seam.md)
- **Status**: `complete`
- **Priority**: `critical`
- **Effort**: `L` (2-4h)
- **Dependencies**: ES-001

## Context

Supersedes [BL-004](../08-backlog/BL-004.md). BL-004 wanted a persisted event journal for replay;
the scope here is narrower and more urgent: an in-engine, append-only event list that agent seats
read as their "what happened" history, with private events (e.g. which tile was drawn) separated
from public ones. Persistence to disk and full event-sourced replay are not in this story (see
Non-goals). Event shapes are defined in [seat-contract](../../../architecture/seat-contract.md).

## Requirements

- `game.events`: list of dicts `{"seq", "type", "player_id", "private_to", ...payload}` emitted on
  every state mutation.
- `public_events(game, viewer_id=None)` returns events with `private_to in (None, viewer_id)`.
- Event types as listed in the contract, including trade events and `tiles_replaced`.
- `seq` is contiguous from 0.

## Acceptance Criteria

- [x] Every successful action appends at least one event; failed actions append none (asserted for every action of every fuzzed game in `run_random_game`; failures compare a state fingerprint).
- [x] A full game's event list reconstructs the final standings and the sequence of turns (`tests/event_ledger.py` derives cash, holdings, standings with ranks and the turn sequence from events only; checked on every fuzzed game).
- [x] `public_events(game, "p2")` never contains p1's `tiles_dealt` / `tile_drawn`.
- [x] Money/stock effects in events (bonuses, purchases) sum to the engine's final holdings (the ledger's cash and per-player/bank stock counts equal the engine's after every action of every fuzzed game).
- [x] JSON-serialisable (`json.dumps` round trip).
- [x] BL-004 status set to `superseded` with a pointer here.

**Status note (2026-11-14):** all criteria met; the three property checks run inside the fuzz
driver (`test_decisions.run_random_game`, so also in the 600-game slow run), with self-tests that
a tampered event breaks the reconciliation. The bank's stock is not settled at game end by the
engine (players' stock is set to 0 without returning it), so the ledger checks the bank up to the
last action before `game_ended`.

## Non-goals

- Writing events to disk; replay by re-applying events (snapshots + action lists cover the test need; see ES-003 and TP-001).
