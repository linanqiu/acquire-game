# TP-002: Scripted Seats

## Metadata
- **Epic**: [Test Pyramid](../../epics/11-test-pyramid.md)
- **Status**: `in-progress`
- **Priority**: `high`
- **Effort**: `M` (1-2h)
- **Dependencies**: ES-005, ES-006

## Context

Tests need opponents that are deterministic and fast, unlike live heuristic bots with random
choices. A scripted seat is an `Agent` (`kind: "scripted"`) from the
[seat contract](../../../architecture/seat-contract.md); the engine cannot tell it from a human.

## Requirements

- `agents/scripted.py`: takes a list of action dicts consumed in order, one per decision; with no
  script, plays the first legal action.
- Each scripted action is validated like any other. An illegal scripted action **fails the test
  loudly** (raises/records an error visible to the test), it does not silently fall back to the
  heuristic. (Unlike LLM/heuristic seats, a script bug is a test bug.)
- Script exhausted: configurable `on_exhausted`: `first_legal` (default) or `error`.
- Script entries may be conditioned on decision kind (`{"when": "buy_stocks", "action": {...}}`) so
  scripts survive small ordering changes.
- Available through `add-seat` with `agent_id: "scripted"` in test mode only; usable directly in
  in-process tests.

## Acceptance Criteria

- [ ] Scripted seat plays a full game in-process with no script.
- [ ] Illegal scripted action produces a visible test failure with the decision context in the message.
- [ ] Conditioned entries work and unknown decision kinds are reported.
- [ ] Same code path as humans verified: a test shows scripted actions appear in the event log identically to the same actions sent as a human.

## Verification

```bash
pytest backend/tests -q -k scripted
```
