# TP-004: Tier-3 Screen Tests

## Metadata
- **Epic**: [Test Pyramid](../../epics/11-test-pyramid.md)
- **Status**: `complete`
- **Priority**: `high`
- **Effort**: `L` (2-4h)
- **Dependencies**: TP-001, TP-002

## Context

One screen state per test, reached by loading a real-play snapshot (TP-001) instead of playing 30
turns through the browser. The rules are not re-tested here; this tier checks that each screen
renders the state correctly and that its controls send the right action.

## Requirements

- `npm run e2e:screens` runs Playwright against real backend (`GAME_TEST_MODE=1`) and frontend.
- Setup per test: create the room and seats (a helper may use the API; this tier is allowed to),
  load a named snapshot via `POST /test/room/{code}/load-snapshot`, open the page in the browser as
  the right player/host, with scripted opponents where an opponent must act.
- Each test: assert what the screen shows (tiles in rack, enabled/disabled controls, prices,
  disposition limits, bonuses shown), perform the UI action, assert the resulting state, and take a
  screenshot at every step.
- Screens/modals to cover, from the surface coverage map: place tile, found chain selector, merger
  survivor choice, stock disposition, buy stocks, trade builder modal, incoming trade offer,
  waiting-for-other-player, thinking indicator (fake LLM seat), end-game declaration, game over
  (player and host), host board view, connection-lost/reconnecting overlay, connection error.
- Console errors and page errors fail the test.
- Tests are independent and can run in parallel (one room each).

## Acceptance Criteria

- [x] Every phase-screen and modal row in `docs/tests/surface-coverage.md` that is assigned to tier 3 names a passing test here (checked by `scripts/check-surface-coverage.py`). Exception: the thinking indicator (PG-12, HO-05) has no stable state to look at (scripted seats answer instantly, no delay option in test mode); it is asserted in journeys J1/J4 and tracked in [TP-009](TP-009.md).
- [x] No test plays more than a few turns (each plays 2-3 follow-up turns after the screen under test). Deviation, per CLAUDE.md: the room is created through the home page UI and the snapshot is loaded into it (the guard rail against skipping the entry points); no screen test walks the home page's forms beyond that, which is tier 4.
- [x] Whole tier finishes in under 5 minutes locally (57 tests, about 2.1 minutes with default workers).
- [x] Screenshots saved under `frontend/test-results/screens/<test-name>/NN-*.png` (`shots.take()`).
- [x] A test that cannot find its expected control fails; no early `return`.
- [x] Any bug surfaced is fixed at the root or filed as a story, never worked around in the test (see the retirement record for the one finding left: the connection-error screen is unreachable by a real handshake failure).
