# TP-001: Snapshot Fixture Generator with Provenance Check

## Metadata
- **Epic**: [Test Pyramid](../../epics/11-test-pyramid.md)
- **Status**: `in-progress`
- **Priority**: `critical`
- **Effort**: `L` (2-4h)
- **Dependencies**: ES-003

## Context

Tier-3 screen tests start from snapshots. The owner was burned by tests built on contrived state
that looked good on coverage and hid real bugs. Guard rail: **every snapshot fixture is produced by
real play and can be proven so.** No hand-built snapshots.

## Requirements

- A fixture spec file (e.g. `backend/tests/fixtures/snapshots/specs.json`): for each fixture, a
  name, a seed, a player/seat setup, and an **action list** (wire-format actions per player) that is
  played from the start of a game until the target state.
- Generator script (`scripts/gen-snapshots.py`): replays each spec through the engine
  (`apply_action` only), asserts the stop condition (e.g. "pending decision is `stock_disposition`
  for player p1"), and writes `to_snapshot()` output to a checked-in JSON file.
- Provenance: each snapshot file embeds `{seed, actions_sha256, generator_version, engine_commit}`.
- Backend test regenerates every fixture and compares byte-for-byte with the checked-in file. It
  fails if a snapshot has no spec, or a spec's output differs (engine change => regenerate on
  purpose).
- Fixtures cover at least one per game phase screen and modal in
  [surface-coverage](../../../tests/surface-coverage.md): place tile (with dead/playable tiles),
  found chain, merger survivor choice, stock disposition, buy phase, buy phase with pending trade
  offer, end-game available, game over, mid-game for host view.
- A helper that finds the shortest or a short real action list (e.g. by seeded search over legal
  actions) is allowed to *produce* a spec; the spec is still replayed by the generator.

## Acceptance Criteria

- [ ] `python scripts/gen-snapshots.py` is deterministic (run twice, no diff).
- [ ] Provenance test fails if a snapshot file is edited by hand.
- [ ] Provenance test fails if a snapshot has no spec.
- [ ] Every fixture's target decision/phase is asserted by the generator, not assumed.
- [ ] Fixtures for every phase screen listed above exist.
- [ ] CLAUDE.md Testing section references this guard rail (done in the 2026-11-14 doc update; keep in sync).

## Verification

```bash
python scripts/gen-snapshots.py && git diff --exit-code backend/tests/fixtures/snapshots
pytest backend/tests -q -k snapshot_provenance
```
