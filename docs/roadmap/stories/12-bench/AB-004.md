# AB-004: Standalone Eval (CLI, Python API, Exit Codes, JSON Output, CI Workflow)

## Metadata
- **Epic**: [Transcripts & Acquire Bench](../../epics/12-acquire-bench.md)
- **Status**: `in-progress`
- **Priority**: `critical`
- **Effort**: `L` (2-4h)
- **Dependencies**: AB-001 (transcripts), AB-005 (protocol)

## Context

Owner decision 2026-11-14: Acquire Bench must be runnable programmatically, on its own: a
standalone command and a Python API with machine-readable output and meaningful exit codes, no
server or browser, usable from CI or a script. The harness `backend/bench` (LO-006) already plays
games headlessly and has a CLI (`python -m bench`, run from `backend/`) with exit codes 0/1/2, but
it takes free-form `--matchup` lists, has no protocol, writes no transcripts, and its Python entry
points (`run_game`, `run_series`) are async and internal in shape.

## Requirements

- **CLI**: keep `python -m bench` working; add protocol mode, e.g.
  `python -m bench run --protocol acquire-bench-v1 --model llm:<id> [--model ...] [--games N]
  [--out DIR] [--max-usd X] [--max-decisions N] [--json]`. Existing flags keep their meaning;
  the free-form `--matchup` mode stays for exploration and its results are marked
  `protocol: null` (never listed on the leaderboard). Subcommands the implementer finalises:
  `run`, `report` (rebuild report from a results dir), `list-protocols`. **Planned, not yet
  implemented.**
- **Python API**: a synchronous, documented function, e.g.
  `bench.run(protocol="acquire-bench-v1", models=[...], games=N, out_dir=..., budget=...) ->
  BenchResult`, plus `bench.report(out_dir) -> dict`. Callable from a plain script or a test
  without an event loop running; returns the report as a dict and the paths of the files written.
  Agents can be injected (a seat may be an agent object or a factory) so a script can benchmark its
  own agent.
- **Output**: a results directory containing `results.jsonl` (resumable, as now), `transcripts/`
  (one file per game, AB-001 format), `report.json` (stable, versioned schema: `schema_version`,
  `protocol`, `prompt_version`, agents, series, per-game records, budget, warnings, `complete`)
  and `report.md`. JSON goes to stdout with `--json` and nothing else is printed to stdout in that
  mode (progress on stderr).
- **Exit codes** (documented in `docs/ai/benchmarking.md` and `--help`): `0` all planned games
  finished; `1` stopped early (budget) or some game stalled; `2` configuration error (unknown or
  unavailable model, missing price with `--max-usd`, bad flags); `3` internal error / crash.
  A run never exits 0 with missing games.
- No server, browser or network needed for the offline fake provider path; real models need their
  API key and fail fast with exit 2 and a clear message when it is absent.
- **CI workflow**: `.github/workflows/bench.yml` (separate from `ci.yml`): on pull requests that
  touch `backend/bench`, `backend/agents` or `backend/game`, run the protocol with the fake
  provider and bots (small game count), assert exit 0, validate `report.json` against its schema
  and upload the results directory as an artifact. A manually-triggered (`workflow_dispatch`)
  variant runs a real model when the `ANTHROPIC_API_KEY` secret is set, with `--max-usd` required.

## Acceptance Criteria

- [ ] `python -m bench run ...` (final syntax documented) with the fake provider finishes, exits 0,
      writes `results.jsonl`, `transcripts/`, `report.json`, `report.md`.
- [ ] `--json` prints exactly one JSON document on stdout; it validates against the report schema
      checked into the repo.
- [ ] Exit code tests: `0` complete; `1` with `--max-decisions` tripped (partial report says
      so); `2` for unknown model, unavailable model (no key) and `--max-usd` with unpriced model;
      `3` when an injected agent raises an unhandled error.
- [ ] Python API test: from a plain function (no running loop) `bench.run(...)` returns a result
      whose report equals the `report.json` on disk; an injected custom agent plays and appears
      in the report.
- [ ] Re-running the same command resumes (no duplicate games, no duplicate transcripts).
- [ ] Same protocol + seeds + fake provider produces byte-identical `results.jsonl` game records
      on two runs.
- [ ] `bench.yml` runs on a PR touching `backend/bench`, goes green, and fails if the CLI exits
      non-zero (verified by a deliberately broken branch or a recorded workflow run noted in the
      story).
- [ ] `import bench` does not import FastAPI or Starlette (test over `sys.modules`). Today it does, transitively: `bench/runner.py` imports `_check`, `_category`, `_timeout_for` from `seats.py`, which pulls in the web app. Move those shared helpers into a module without web dependencies and import them from both `seats.py` and `bench`, so the one decide/check step stays shared and the standalone package installs and runs without a server stack.
- [ ] `docs/ai/benchmarking.md` command table matches `--help` output.

## Implementation Notes

- Wrap, do not rewrite: `bench.series.run_series` stays the engine; add `asyncio.run` in the
  synchronous API. Existing tests in `backend/tests/test_bench.py` must keep passing.
- Report schema as JSON Schema under `backend/bench/schema/report.schema.json` and a test that
  validates a generated report against it.
- Cost guard behaviour is unchanged (`--max-usd` needs known prices).
