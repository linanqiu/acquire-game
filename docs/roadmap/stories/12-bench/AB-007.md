# AB-007: Leaderboard UI

## Metadata
- **Epic**: [Transcripts & Acquire Bench](../../epics/12-acquire-bench.md)
- **Status**: `in-progress`
- **Priority**: `high`
- **Effort**: `M` (1-2h)
- **Dependencies**: AB-002 (transcript routes), AB-006 (leaderboard document)

## Context

Acquire Bench is a product feature (owner decision 2026-11-14): visitors should see how the
models rank at Acquire, how sure we are, what it cost, and be able to open the games behind each
number.

## Requirements

- Route `/bench` linked from the home page and header. Shows the current protocol (id, prompt
  version, games per matchup, seed list note) and a table, one row per agent: rank, label and
  model, games, win rate with interval, mean rank, rating with interval, retry rate, fallback rate
  (with reasons on hover/expand), tokens per game, cost per game (`unknown` when null), median
  latency, verdict.
- Plain language footer: how rating is computed (link to the doc), what the protocol is, that
  bots are the baseline, and that small samples are marked.
- Rows with too few games are visibly separate ("insufficient games") and not ranked.
- Each row expands to the series and links to each game's transcript (`/games/:gameId`), with
  games containing fallbacks flagged.
- States: loading, error with retry, and empty ("No benchmark results yet" plus how results are
  produced, naming the standalone command from `docs/ai/benchmarking.md`). Never shows a leaderboard
  from mixed protocol versions; a protocol selector appears only if more than one exists.
- Uses existing components and tokens; works at phone width.

## Acceptance Criteria

- [ ] Vitest: renders rows from a mocked `/bench/leaderboard`, shows `unknown` for null cost,
      shows the insufficient-games section, shows reasons for fallbacks.
- [ ] Vitest: empty and error states.
- [ ] Vitest: expanding a row lists links to `/games/:id` matching the ids in the response.
- [ ] Tier-3 screen test with a checked-in leaderboard fixture generated by running the real
      harness with the fake provider (not hand-written), screenshots at desktop and phone width.
- [ ] Surface coverage map has rows for `/bench` and its states, each naming a test.
- [ ] No number is shown that is not in the API response (no client-side invented values).

## Implementation Notes

- Fixture generation: run `bench` with the fake provider, store the leaderboard JSON next to the
  other generated fixtures with a provenance note.
