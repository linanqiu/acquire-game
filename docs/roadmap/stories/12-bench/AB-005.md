# AB-005: Protocol `acquire-bench-v1`

## Metadata
- **Epic**: [Transcripts & Acquire Bench](../../epics/12-acquire-bench.md)
- **Status**: `in-progress`
- **Priority**: `critical`
- **Effort**: `M` (1-2h)
- **Dependencies**: LO-006 (the existing `backend/bench` harness)

## Context

A benchmark is only meaningful if everyone plays the same games the same way. The seat contract
names the protocol (`acquire-bench-v1`: fixed seed list, 4 seats, full seat rotation, fixed prompt
version, two tracks). This story turns that into a definition the code enforces. Results are
comparable only within a protocol id plus prompt version; nothing is mixed across them.

## Requirements

A protocol is a checked-in, immutable definition (suggested `backend/bench/protocols/
acquire_bench_v1.py` or JSON) loadable by id:

- `id`, `description`, `players` (4), `seeds` (a fixed explicit list; game `i` of a matchup uses
  `seeds[i]`; list long enough for the maximum game count, e.g. 200), `games_per_matchup` (default,
  and the minimum for the leaderboard to show a verdict), `rotation` (all 4 rotations, equally
  often: games per matchup is a multiple of 4), `prompt_version` (the hash from the transcript
  header; the protocol pins one value and a run with a different prompt version is refused),
  `decision_timeout`, `max_retries` (LO-003 default, 4), `turn_cap`/runaway limits as in the
  server.
- **Track vs-baseline**: the model under test in one seat, three rules-based bots (`bot`) in the
  others, each model on the same seeds and rotations. Reports win rate (a tie counts as a split
  win), mean rank, score margin vs the bots.
- **Track head-to-head**: models of different strength in the same game (e.g. two models plus two
  bots, or 4 models); matchup list defined by the protocol or supplied by the caller from the
  models under test, always paired on the same seeds and rotations.
- A **baseline control**: `bot,bot,bot,bot` on the same seeds, run once per protocol version, so
  the "chance" level and bot self-play are visible and checked (roughly equal win rates; see
  AB-006 for the check).
- **Version rules**: changing seeds, seat count, rotation, prompt text, retry limit, timeouts or
  scoring requires a new id (`acquire-bench-v2`). A prompt change alone bumps `prompt_version`;
  the protocol either re-pins (new id) or refuses. Old results stay under the old id and are never
  merged. Every result record, transcript header and report stores `protocol` and
  `prompt_version`.
- The runner (AB-004) refuses to start a protocol run if the current prompt version differs from
  the pinned one, with exit 2 and a message that says what to do.

## Acceptance Criteria

- [ ] `list-protocols` (or `bench.protocols()`) returns `acquire-bench-v1` with its parameters.
- [ ] The seed list is explicit in the repo, deterministic, and has no duplicates; a test pins its
      hash so an accidental edit fails.
- [ ] Over any 4 consecutive games of a matchup every model sits in every position once (test on
      the plan, not on game results).
- [ ] Two matchups in the same run see identical seeds and rotations per game index.
- [ ] A run with a mismatched prompt version exits 2 without playing a game.
- [ ] Result records and transcripts carry `protocol` and `prompt_version`; a loader asked for
      `acquire-bench-v1` ignores records of other protocol ids or prompt versions and says how many
      it skipped.
- [ ] `docs/ai/benchmarking.md` describes both tracks, the seed list location and the version
      rules.

## Implementation Notes

- Existing `bench.series.plan` / `rotate` already do seed and rotation for free-form matchups;
  the protocol fixes their inputs.
- Free-form `--matchup` runs remain available and are labelled `protocol: null`.
