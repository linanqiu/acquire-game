# AB-003: Transcript Browser and Replay Viewer UI

## Metadata
- **Epic**: [Transcripts & Acquire Bench](../../epics/12-acquire-bench.md)
- **Status**: `in-progress`
- **Priority**: `high`
- **Effort**: `L` (2-4h)
- **Dependencies**: AB-002

## Context

Users are curious how the AI seats think. They should be able to open recent games and step
through them, seeing for each AI decision the prompt, the model's answer, its stated reasoning,
any rejected attempts and retries, and any fallback. For a game still in progress the server
sends a redacted transcript (AB-002), so the viewer shows what the server gives it and says what
is hidden until the game ends.

## Requirements

- Routes: `/games` (list of recent games, filter live/bench) and `/games/:gameId` (replay). A link
  to `/games` from the home page; a link to the replay from the game-over screen (uses `game_id`).
- List rows: seats (name, kind badge, model), status (live / finished / abandoned), winner(s),
  turns, started time, source.
- Replay: board and player panel rebuilt from the `state` entries of the transcript (public state
  only), with controls: previous / next entry, jump to start/end, jump to next/previous decision
  of a chosen seat, and a position indicator. Keyboard arrows work.
- Decision panel for the current entry: seat, decision kind, legal options (when not redacted),
  the applied action, source (`human|bot|scripted|llm|fallback`), latency. For LLM decisions:
  system prompt (collapsible, shown once per game), user prompt, each attempt in order (raw output,
  rejection reason, retry prompt), `why`, `note`, tokens, cost when known.
- Fallbacks are visibly marked in the step list and in the decision panel with the reason.
- Redacted transcripts show a banner ("Hands and AI notes are hidden until this game ends") and
  omit the hidden fields without errors.
- Large transcripts: the step list is virtualised or paginated; a 6-player full game opens
  without freezing the page (state entries are loaded once; stepping is client-side).
- Reuses existing components (`Board`, `PlayerCard`, `Portfolio` where they fit); no new design
  tokens.

## Acceptance Criteria

- [ ] Vitest: list renders rows from a mocked `/games` response, including a live and an
      abandoned game; empty state shown when there are no games.
- [ ] Vitest: stepping forward/backward changes the board and the decision panel; first/last
      positions disable the corresponding buttons.
- [ ] Vitest: a decision with two rejected attempts and a final fallback shows all attempts, the
      retry prompts and the fallback marker.
- [ ] Vitest: a redacted transcript renders the banner and no empty "undefined" sections.
- [ ] Tier-3 screen test (snapshot-free: loads a checked-in finished-game transcript fixture
      served by a test-mode route or mocked route) for the replay page, with screenshots.
- [ ] Tier-4 journey step: after playing a short game with an AI seat from the home page, open its
      replay from the game-over screen and step to an AI decision (screenshot of prompt and
      answer).
- [ ] `docs/tests/surface-coverage.md` has rows for `/games` and `/games/:gameId` and their
      states, each naming a test.

## Implementation Notes

- Transcript fixtures for tests are generated by running a real game through AB-001's writer, not
  written by hand (same provenance rule as snapshots; see Epic 11).
- Keep pure transcript-to-view-model logic in `frontend/src/lib/` so it is unit-testable without
  React.
