# AB-008: Transcript Persistence and Retention in Deployment

## Metadata
- **Epic**: [Transcripts & Acquire Bench](../../epics/12-acquire-bench.md)
- **Status**: `not-started`
- **Priority**: `medium`
- **Effort**: `M` (1-2h)
- **Dependencies**: AB-001
- **Blocked by**: owner decision and action: attach a persistent volume to the Railway service and
  choose a retention limit. Without a volume the container file system is discarded on every
  redeploy and restart.

## Context

The deployment is one Railway service, single replica ([deploy/README.md](../../../../deploy/README.md)).
Game state is in memory and ends on restart; transcripts are files under
`ACQUIRE_TRANSCRIPT_DIR`. If the directory is on the container's own disk, every redeploy deletes
all transcripts and the published benchmark games with them. Open item (Epic 12).

## Requirements

- Document the deployment requirement in `deploy/README.md`: mount a volume (for example at
  `/data`), set `ACQUIRE_TRANSCRIPT_DIR=/data/transcripts` (and the bench results directory under
  it). State plainly what is lost without a volume.
- `Dockerfile` / `railway.toml`: nothing hard-codes a path that needs root-owned storage; the app
  creates the directory if it is missing and fails clearly (log + `/health` detail) if it is not
  writable.
- Retention: configurable maximum total size and maximum age for **live** (non-bench) transcripts
  (for example `ACQUIRE_TRANSCRIPT_MAX_MB`, `ACQUIRE_TRANSCRIPT_MAX_DAYS`); pruning deletes oldest
  finished live games first, runs at start-up and periodically, never deletes a game in progress,
  and **never deletes transcripts referenced by a published benchmark series** (bench transcripts
  are kept until explicitly removed by an operator).
- `/health` (or `GET /games` metadata) reports whether the transcript directory is persistent as
  far as the app can tell (a marker file written at first start and still present after restart),
  so the UI can show "transcripts are not kept across restarts" instead of silently losing them.
- Document backup/export for bench transcripts (a plain directory copy or tarball command).

## Acceptance Criteria

- [ ] `deploy/README.md` has the volume steps, variables and the consequence of skipping it.
- [ ] Unit tests for pruning: size limit, age limit, in-progress game kept, bench-series
      transcripts kept.
- [ ] Unwritable directory: app starts, games run, error is logged once and visible in `/health`.
- [ ] The transcript list UI (AB-003) shows a notice when the directory is not persistent.
- [ ] Verified on a real Railway deploy with a volume: play a game, redeploy, the game is still
      listed (recorded in the story with date). Not done until the owner attaches the volume.
- [ ] Open item in Epic 12 closed or restated.
