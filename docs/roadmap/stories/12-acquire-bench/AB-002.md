# AB-002: Transcript HTTP API with Redaction

## Metadata
- **Epic**: [Transcripts & Acquire Bench](../../epics/12-acquire-bench.md)
- **Status**: `in-progress`
- **Priority**: `critical`
- **Effort**: `M` (1-2h)
- **Dependencies**: AB-001

## Context

Users browse recent games and replay them. A game in progress must not leak hands or private model
notes; after it ends everything is public. The privacy rule and routes are defined in the
[seat contract](../../../architecture/seat-contract.md) ("Privacy rule", "HTTP"). Redaction happens
on the server, so no client can bypass it.

## Requirements

Routes (also under `/api`, like the rest of the API):

- `GET /games?source=live|bench&limit=50&before=<game_id>`: newest first; summary per the contract
  (`game_id, source, status live|finished|abandoned, started_at, ended_at, room_code, series_id,
  seats, winners, turns`).
- `GET /games/{game_id}`: summary plus `standings` and `totals`.
- `GET /games/{game_id}/transcript`: `{header, entries, footer, redacted}`.
- Redaction while there is no footer and the game is live: drop events with `private_to`, and from
  each decision `llm.user_prompt`, `attempts[].raw`, `attempts[].retry_prompt`, `why`, `note` and
  the tile lists inside `legal`. `redacted: true`. After the footer: full content, `redacted: false`.
- A transcript with no footer whose game is no longer running in this process (server restarted)
  is `abandoned` and treated as finished for redaction purposes (its hands can no longer matter).
- `game_id` is validated (URL-safe pattern) and resolved only inside the transcript directory: no
  path traversal.
- Listing reads an index kept in memory and rebuilt from the files at start-up; it must stay fast
  with thousands of files (read headers/footers only).
- `game_state` and the game-over WebSocket message carry `game_id` (contract), so clients can link
  to `/games/{game_id}`.
- Read-only: no route modifies or deletes transcripts.

## Acceptance Criteria

- [ ] Listing returns games newest first, honours `source`, `limit` and `before`, and includes a
      game that is still running with `status: "live"`.
- [ ] While a game with an LLM seat is running, the transcript response contains none of: another
      seat's tiles anywhere in the payload (string search over the JSON for every tile in every
      hand), `user_prompt`, `raw`, `retry_prompt`, `why`, `note`; `redacted` is true.
- [ ] After game over the same request returns every field, `redacted` false.
- [ ] Redacted response for a bot-only live game still lets a client reconstruct the public move
      list (event types, tiles placed, purchases, trades).
- [ ] `GET /games/../../etc/passwd`-style ids and unknown ids return 404, never read outside the
      directory.
- [ ] Standings and totals in `GET /games/{id}` equal the footer.
- [ ] `game_id` appears in `game_state` and the game-over message for live games.
- [ ] Contract HTTP table matches the implemented response shapes (update in the same commit).

## Implementation Notes

- Suggested `backend/api/games.py` router and `backend/transcripts/store.py` (index, reading,
  redaction as a pure function `redact(entries) -> entries`, unit-tested on its own).
- Determine "live" from the room registry (a room with a running game and this `game_id`), not
  from file age.
