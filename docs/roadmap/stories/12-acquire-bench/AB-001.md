# AB-001: Transcript Writer (Server Driver and Bench Runner)

## Metadata
- **Epic**: [Transcripts & Acquire Bench](../../epics/12-acquire-bench.md)
- **Status**: `in-progress`
- **Priority**: `critical`
- **Effort**: `L` (2-4h)
- **Dependencies**: ES-002 (event log), LO-003 (decision loop; retry attempts come from it)

## Context

Owner decision 2026-11-14: every game keeps a complete transcript (all moves; for AI seats the
exact prompt and the exact model output, including rejected attempts). It serves testing and
debugging, and user curiosity. The format is fixed by the
[seat contract](../../../architecture/seat-contract.md), "Game transcripts and Acquire Bench";
that section wins if this text disagrees.

Today the only prompt-level record is `agents/llm/decision_log.py` (per agent, JSONL only when
`ACQUIRE_LLM_LOG_DIR` is set, repair counted but the retry prompt not stored). It does not record
human or bot decisions, engine events or public state. It is superseded by this story (LO-007).

## Requirements

- A `TranscriptWriter` (suggested `backend/transcripts/writer.py`) writing
  `<ACQUIRE_TRANSCRIPT_DIR>/<game_id>.jsonl` (default `backend/data/transcripts/`, git-ignored;
  URL-safe unique `game_id`). Line types: `header`, `event`, `decision`, `state`, `footer`, with the
  fields in the contract.
- One writer, two callers: the server driver (`seats.py`, covering human, bot, scripted and LLM
  decisions through the one action path) and the bench runner (`bench/runner.py`). Neither builds
  transcript lines itself.
- `decision.llm.attempts[]` holds every model call for that decision: raw output, parsed action,
  rejection reason, latency, tokens, and the full retry prompt that followed it. The agent must
  expose these (extend `LLMAgent` to return/record attempts; keep the ring buffer if still used).
- `fallback` is filled on every fallback (reason `timeout|error|illegal|cap`, message), and the
  decision's `source` is `fallback`.
- `header.prompt_version` is a hash of the system prompt plus a prompt-builder version constant;
  `system_prompts` holds the full text once per game, decisions reference it by id.
- Append-only, flushed per line, so a crashed server leaves a readable file without a footer
  (`abandoned`). A game that ends because the host forces it records `reason: "forced"`.
- Write failures (disk full, bad path) are logged and never stall or fail the game.
- Nothing is sampled or truncated. API keys and auth headers never appear (the writer only
  receives what the agent returns; add a test).

## Acceptance Criteria

- [ ] A live game with a human, a bot and a fake-provider LLM seat produces one file with header,
      one `event` line per engine event (same count and `seq` values as `game.events`), one
      `decision` line per applied decision, a `state` line after each applied action, and a footer.
- [ ] Human and bot decisions appear with `llm: null`; LLM decisions carry `user_prompt`,
      `system_prompt_id` and `attempts[]`.
- [ ] Fake provider returning illegal, then illegal, then legal: three `attempts` entries with
      `error` set on the first two and a `retry_prompt` on each rejected one.
- [ ] A forced fallback (timeout, provider error, exhausted retries) records `source: "fallback"`
      and the `fallback` object; a game with a failing LLM seat still completes.
- [ ] Bench games write the same format with `source: "bench"` and the `bench` block
      (`series_id, matchup, seed, rotation`); a transcript written by the bench runner and one by
      the server for the same seed and seats have identical `event` lines.
- [ ] Footer `totals` per player match the counters in the bench report for the same game
      (decisions, retries, fallbacks, tokens).
- [ ] Killing the writer mid-game leaves a file whose every line parses as JSON and has no footer.
- [ ] An unwritable `ACQUIRE_TRANSCRIPT_DIR` does not stop a game (test).
- [ ] No test or fixture transcript contains an API key string (test with a fake key in the env).
- [ ] Contract section updated in the same commit if the format changes.

## Implementation Notes

- Hook in `seats._drive_loop` / `apply_and_publish` (one call site for all seats) and in
  `bench.runner.run_game`; prefer a small interface (`on_event`, `on_decision`, `on_state`,
  `close`) so tests can substitute an in-memory writer.
- `after_seq` on `decision` and `state` lines is the last event `seq` at that moment; the viewer
  (AB-003) relies on it for stepping.
- Public state is `game.get_public_state()`; store it as is.
