# AB-006: Ratings and Leaderboard Computation

## Metadata
- **Epic**: [Transcripts & Acquire Bench](../../epics/12-acquire-bench.md)
- **Status**: `in-progress`
- **Priority**: `high`
- **Effort**: `L` (2-4h)
- **Dependencies**: AB-005 (protocol), AB-001 (transcript links)

## Context

The leaderboard must be honest about uncertainty and cost, and every row must link to the
transcripts behind it (owner decision 2026-11-14). The existing report (`backend/bench/report.py`)
already computes per-matchup win rate with a Wilson interval, mean rank, score margin vs bot,
fallback and repair rates, latency, tokens and cost. This story adds the cross-matchup rating and
the leaderboard document served at `GET /bench/leaderboard`.

## Requirements

- A rating per agent computed from finishing orders across all games of one protocol id plus
  prompt version (never across versions). The method is fixed and documented in
  `docs/ai/benchmarking.md` (suggested: a Plackett-Luce / Bradley-Terry style maximum-likelihood fit
  on finishing order with ties handled as split, anchored so the rules-based bot is 1000, with a
  bootstrap over games for `rating_ci`). Changing the method requires a new protocol id.
- Leaderboard document (shape in the seat contract): per agent `games, wins, win_rate, ci_low,
  ci_high, mean_rank, rating, rating_ci, fallback_rate, retry_rate, tokens_per_game,
  cost_per_game (null when a price is unknown), latency_p50_s, verdict`, plus the protocol block
  and the list of series.
- **Retries and fallbacks are separate columns** (decision 3): `retry_rate` = decisions that
  needed at least one retry; also `retries_per_decision`; `fallback_rate` with the breakdown by
  reason `timeout|error|illegal|cap`.
- **Sample size honesty**: each row shows `games`; a row with fewer than the protocol minimum of
  games gets `verdict: "insufficient games"` and is sorted below rated rows; verdicts compare the
  interval with chance, as the current report does; the document includes the number of games
  needed to separate two ratings of the observed gap where computable.
- **Cost honesty**: `cost_per_game` is `null` and rendered `unknown` unless every price needed is
  in `prices.json`; the document carries `prices_as_of` and the source names; total spend of the
  run is shown.
- **Links**: each agent row includes `game_ids` (or a query that resolves to them) so the UI can
  link to `/games/{id}` for every game and highlight the games with fallbacks.
- **Baseline check**: the `bot,bot,bot,bot` control in the protocol is included, and the document
  includes a `baseline_check` (win rates within chance interval) so a broken harness is visible.
- Series with a different `prompt_version` are listed under `excluded` with counts, not merged.
- Implemented as a pure function over result records, shared by the CLI report and the HTTP route.
- `GET /bench/leaderboard?protocol=<id>` and `GET /bench/series/{series_id}` (contract) served
  from results found under the configured bench results directory (and the transcript store).

## Acceptance Criteria

- [ ] Rating function hand-checked on a small synthetic set of finishing orders (documented
      expected values), including a tie and a sweep.
- [ ] Rating is invariant to game order and to seat rotation labels; a test shuffles records.
- [ ] A synthetic agent that always wins gets a higher rating and a non-overlapping interval
      versus the bot with enough games; with few games the verdict is `insufficient games` or
      `inconclusive`.
- [ ] Records from two prompt versions never appear in one leaderboard (test); the excluded counts
      are reported.
- [ ] `cost_per_game` is `null` for an unpriced model and a number for a priced fake model; no
      zero-for-unknown.
- [ ] Retry and fallback rates differ in a scripted case where an agent retries often but never
      falls back.
- [ ] `/bench/leaderboard` response validates against the shape in the seat contract; each agent
      has links/ids that all resolve through `GET /games/{id}`.
- [ ] Baseline check present; an artificially skewed baseline makes it fail visibly.
- [ ] Method and its limits written up in `docs/ai/benchmarking.md`.

## Implementation Notes

- Reuse `bench.report.wilson`, `mean_ci`, `assign_ranks`; do not duplicate the interval maths.
- Seat-games from one multi-seat agent are not independent (known limit in the benchmarking doc);
  keep that warning in the document.
