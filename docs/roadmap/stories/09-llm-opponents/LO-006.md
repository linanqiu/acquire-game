# LO-006: Benchmark Harness (LLM vs Heuristic)

## Metadata
- **Epic**: [LLM Opponents](../../epics/09-llm-bot.md)
- **Status**: `in-progress`
- **Priority**: `high`
- **Effort**: `L` (2-4h)
- **Dependencies**: LO-003

## Context

Which model is the default for each tier, and whether any deferred orchestration (Epic 9, Deferred)
is worth building, must be decided by measurement. Games run in-process against the engine, with no
browser and no HTTP.

## Requirements

- CLI: `python -m benchmarks.run --seats llm:<id>,bot,bot,bot --games N --seed S`.
- Plays full games through the decisions API and the same driver/agents as production.
- Seat rotation across games so position bias cancels out; fixed seeds so runs are reproducible.
- Report per seat: games, win rate, mean final net worth, mean rank, fallback rate, repair rate,
  mean/p95 latency per decision, tokens in/out, and **cost per game** (price table in config).
- Output a machine-readable JSON file and a short markdown summary.
- A `--dry-run` using the fake provider so the harness itself is tested in CI without network.
- Cost guard: refuses to start if the estimated cost exceeds `--max-cost` (default small).

## Acceptance Criteria

- [ ] Heuristic vs heuristic baseline runs and shows roughly equal win rates over a few hundred games.
- [ ] Same seed + same agents + fake provider => identical results.
- [ ] Report includes win rate with a confidence interval and cost per game.
- [ ] Harness tested in CI with the fake provider (no network).
- [ ] A results file for the first real run is committed under `docs/ai/benchmarks/` with the tier defaults it justifies.

## Implementation Notes

- Suggested: `backend/benchmarks/`. Do not import FastAPI app code; drive the engine and agents directly.

## Verification

```bash
pytest backend/tests -q -k benchmark
python -m benchmarks.run --seats bot,bot,bot --games 20 --seed 1 --dry-run
```
