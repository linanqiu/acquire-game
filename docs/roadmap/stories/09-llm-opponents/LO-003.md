# LO-003: Decision Loop (Validate, Repair, Fallback)

## Metadata
- **Epic**: [LLM Opponents](../../epics/09-llm-bot.md)
- **Status**: `in-progress`
- **Priority**: `critical`
- **Effort**: `L` (2-4h)
- **Dependencies**: LO-001, LO-002, ES-005 (driver loop)

## Context

The `LLMAgent` implements `Agent.decide(ctx)` from the [seat contract](../../../architecture/seat-contract.md).
v0 is a **single call per decision**. Planner/critic chains are deferred (see Epic 9).

## Requirements

1. Build prompt (LO-002), call provider (LO-001) with a timeout.
2. Parse structured output into an action dict.
3. Validate the answer (structurally in the agent, then `validate_action` in the driver). An illegal
   or unparseable answer is **sent back to the model**: the next prompt lists every earlier rejected
   answer of this decision, the exact reason, and the legal options. Up to `max_illegal_retries`
   (default 4, catalog-overridable) retries after the first attempt, all within the decision's time
   budget. Engine-level rejections reach the agent via `decide(ctx, rejected=[...])` and share the
   same retry budget.
4. Only when the retry budget is exhausted, or on timeout / provider error: the rules-based agent
   decides this one decision (a timeout never retries) and the table is told via `agent_fallback`
   (see the seat contract).
5. The agent returns an action dict only. The driver applies it through `apply_action`, the same
   path as human actions. The agent holds no game reference and never mutates state.
6. A game with an always-failing provider must still finish.

## Acceptance Criteria

- [ ] Valid first answer: exactly one provider call, action applied.
- [x] Illegal first answer then valid retry: exactly two calls; several illegal answers then a legal one: no fallback.
- [x] Always illegal: exactly 1 + `max_illegal_retries` calls, then heuristic fallback (`reason: illegal`), game continues.
- [x] Engine-rejected (structurally legal) answer is retried with the engine's error.
- [x] Timeout / provider exception: immediate heuristic fallback (no retry), game continues.
- [x] Every fallback is announced (`agent_fallback`, `game_state.fallbacks`, frontend toast + seat marker).
- [ ] Full game with fake provider failing 100% completes; with 30% random failures completes.
- [ ] Fuzz test: random provider outputs never produce an illegal state transition (invalid answers are rejected by validation, not by the engine raising).
- [ ] Timeout is configurable per catalog entry; a slow provider does not hold the room lock beyond the driver design in ES-005.
- [ ] Each decision produces one observability record (LO-007) including `fallback: true/false`.

## Implementation Notes

- Suggested: `backend/agents/llm/agent.py`.
- Fallback reuses `agents/heuristic.py`; do not add a second heuristic implementation.
