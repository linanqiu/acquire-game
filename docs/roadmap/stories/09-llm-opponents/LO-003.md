# LO-003: Decision Loop (Validate, Repair, Fallback)

## Metadata
- **Epic**: [LLM Opponents](../../epics/09-llm-bot.md)
- **Status**: `in-progress`
- **Priority**: `critical`
- **Effort**: `L` (2-4h)
- **Dependencies**: LO-001, LO-002, ES-005 (driver loop)

## Context

The `LLMAgent` implements `Agent.decide(ctx)` from the [seat contract](../../../architecture/seat-contract.md).
v0 is a **single call per decision**. Planner/critic chains are deferred (see Epic 9).

## Requirements

1. Build prompt (LO-002), call provider (LO-001) with a timeout.
2. Parse structured output into an action dict.
3. `validate_action(game, player_id, action)`. If it returns an error, **send the answer back to
   the model with the reason (and the legal actions) and let it try again**: default up to **4
   retries**, all inside the decision's time budget (owner decision 2026-11-14; previously one repair
   call). The retry limit is configurable per catalog entry and a setting.
4. Only a **timeout, a provider error, or exhausted retries** hand this one decision to the
   rules-based (heuristic) agent, marked as a fallback. An illegal answer is never itself a
   reason to fall back while retries remain.
4b. **Every fallback is made known to everyone at the table**: a notice (room-wide message naming
   the seat, the decision and the reason) and a persistent marker on that seat in the player lists
   and host view (e.g. a fallback count). It is also recorded in the transcript (AB-001) with the
   reason (`timeout|error|illegal|cap`) and the message.
4c. Retries and fallbacks are counted separately in the totals the benchmark reads (AB-006).
5. The agent returns an action dict only. The driver applies it through `apply_action`, the same
   path as human actions. The agent holds no game reference and never mutates state.
6. A game with an always-failing provider must still finish.

## Acceptance Criteria

- [x] Valid first answer: exactly one provider call, action applied. (`test_valid_first_answer_is_one_call`)
- [ ] Illegal first answer then a valid answer: exactly two calls, no fallback. (Today passes with exactly one repair; must hold under the retry loop.)
- [ ] Illegal on every attempt: the model is called 1 + `max_retries` times (default 5 calls in total), each retry prompt carries the previous error, then the heuristic fallback is used and the game continues.
- [ ] Malformed output counts as an illegal answer and is retried the same way.
- [ ] Timeout or provider exception: heuristic fallback at once, no further retries; game continues.
- [ ] The retry loop respects the decision's time budget: when the budget is spent mid-retry the decision falls back with reason `timeout`.
- [ ] A fallback produces a room-wide notice and a persistent seat marker visible to every client (LO-005 renders it), and a `fallback` entry in the transcript.
- [ ] Retry count and fallback count are reported separately in the agent totals.
- [x] Full game with fake provider failing 100% completes. (`tests/protocol/test_driver.py::test_failing_llm_seats_fall_back_and_game_completes`)
- [ ] Full game with 30% random failures completes.
- [ ] Fuzz test: random provider outputs never produce an illegal state transition (invalid answers are rejected by validation, not by the engine raising).
- [x] Timeout is configurable per catalog entry; a slow provider does not hold the room lock beyond the driver design in ES-005. (Catalog `timeout`; driver releases the lock during `decide`.)
- [ ] Each decision produces one transcript decision entry (AB-001; replaces the LO-007 record) including `fallback`.

**Status note (2026-11-14):** `LLMAgent.decide` in `backend/agents/llm/agent.py` still does one
answer plus one repair (`for attempt in (1, 2)`); the server driver (`seats._drive_loop`) falls back
on exception, timeout or illegal answer; `llm_decision_timeout` is 130 s ("two provider calls").
The 4-retry policy, the notice/marker and the time budget accounting are not built. The benchmark
runner mirrors the server step in `bench.runner._obtain` and must be changed with it.
