# LO-001: Provider Adapters and Agent Catalog/Config

## Metadata
- **Epic**: [LLM Opponents](../../epics/09-llm-bot.md)
- **Status**: `in-progress`
- **Priority**: `high`
- **Effort**: `L` (2-4h)
- **Dependencies**: ES-001 (only for the `Agent` interface shape)

## Context

An LLM seat names its model in config. The July constraint "open-weight only" is lifted
(owner decision 2026-11-14). Providers must be pluggable, and the lobby needs to know which AI
opponents it can offer. See [seat-contract](../../../architecture/seat-contract.md), "HTTP additions".

## Requirements

- A small `LLMProvider` interface: `complete(messages, schema, model, timeout) -> text/JSON`,
  plus usage (input/output tokens) for cost tracking.
- Two adapters: **Anthropic** and **OpenAI-compatible** (`base_url`, key, model).
- A config file/section listing AI opponents: `id`, `label`, `description`, `provider`, `model`,
  `base_url` (where relevant), `api_key_env`, `timeout_s`, `tier`.
- `GET /agents/catalog` returns `[{id, kind, label, description, available}]`. `bot` is always
  present and available. LLM entries are `available` only if their key env var is set.
- A **fake provider** (deterministic, scriptable responses and failures) for tests; selected by
  catalog id, only when `ACQUIRE_TEST_MODE=1`.
- No API keys in logs, responses, or the catalog.

## Acceptance Criteria

- [x] Both adapters implement the same interface; provider choice is config only.
- [x] Catalog endpoint matches the seat contract shape; unavailable entries are marked, not hidden.
- [x] Missing key => `available: false`; adding a seat with an unavailable id returns a clear 4xx.
- [x] Fake provider can return: valid answer, malformed JSON, illegal action, slow response (timeout), error.
- [x] Unit tests for each adapter using recorded/mocked HTTP; no network in tests.
- [ ] Default model per tier is read from config (set from LO-006 results, not hard-coded).

**Decision 2026-11-14 (model availability):** LLM opponents are selectable only when their API key
is configured on the server. Otherwise the lobby shows them disabled and only the rules-based
player (`bot`) can be added. Server side this is already enforced (`add-seat` with an unavailable
id returns 400; the catalog marks `available: false`); the lobby UI disables them (LO-005).

**Status note (2026-11-14):** built in `backend/agents/llm/providers.py` (`AnthropicProvider`,
`OpenAICompatProvider`, `FakeProvider`; `Provider` protocol) and `backend/agents/llm/config.py`
(`CatalogEntry`, env-configured entries, `ACQUIRE_LLM_CATALOG` override); catalog served from
`backend/agents/registry.py`. Only the last criterion is open: catalog entries have no `tier`
field, so there is no per-tier default yet. That waits for the first real benchmark run (AB-009).

## Implementation Notes

- Suggested layout: `backend/agents/llm/providers/{base,anthropic,openai_compat,fake}.py`,
  `backend/agents/catalog.py`.
- Structured output: use the provider's native schema/tool mechanism where available; otherwise
  JSON mode. Validation happens in LO-003, not here.
