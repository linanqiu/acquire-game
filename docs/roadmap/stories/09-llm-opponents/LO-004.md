# LO-004: Trade Responses and Proposals

## Metadata
- **Epic**: [LLM Opponents](../../epics/09-llm-bot.md)
- **Status**: `in-progress`
- **Priority**: `high`
- **Effort**: `M` (1-2h)
- **Dependencies**: LO-003

## Context

Owner decision 2026-11-14: player-to-player trading stays; it is an important fun feature. An LLM
seat that ignores trades would make tables with LLMs feel dead. Wire format and decision shape are
in the [seat contract](../../../architecture/seat-contract.md) (`trade_response` decisions;
`propose_trade` offered in the buy phase).

## Requirements

- **Respond**: when `pending_decisions` includes a `trade_response` addressed to an LLM seat (even
  when it is not that seat's turn), the driver asks the agent; the answer is `accept_trade` or
  `reject_trade`. `can_accept: false` (insufficient holdings) means reject is the only legal answer.
- **Propose**: in the buy phase, `propose_trade` is among the legal action types. The prompt tells
  the model it may propose, and shows who holds what (public holdings from the calculator pack). A
  proposal is optional; "no trade" is the default.
- Bound the behaviour: at most one open proposal per LLM seat; no more than N proposals per turn
  (config, default 1) so a table is not spammed.
- Trade events (`trade_proposed/accepted/rejected/cancelled`) appear in the event log and so in
  later prompts.
- Heuristic bot behaviour on trades is unchanged or explicitly documented in this story.
- Unanswered offers to an LLM seat must not stall the game: fallback = reject.

## Acceptance Criteria

- [ ] LLM seat receives and answers an offer made by a human, on the human's turn and the LLM's off-turn.
- [ ] LLM seat can propose a trade to a human; the human UI shows it (depends on frontend trade-offer UI; if absent, add a story and note it in the surface coverage map).
- [ ] Provider failure on a trade response results in reject; the game continues.
- [x] Proposal limit is enforced by the driver, not just requested in the prompt.
- [ ] Tier-2 test: human (scripted) <-> LLM (fake provider) trade round trip including accept and reject.

**Status note (2026-11-14):** `LLMAgent` handles `trade_response` and `propose_trade`
(`tests/test_llm_agent.py`: accept/reject, one proposal per turn, affordability); the driver caps
proposals per seat per turn (`max_trade_proposals_per_turn`, `test_runaway_trade_proposals_are_capped`);
off-turn answering while the agent is thinking is tested with a gate agent. Open: (a) a tier-2
round trip human <-> fake-provider LLM covering both accept and reject (the bot-accepts and
LLM-rejects cases are tested separately); (b) the failure criterion: a failed trade-response
decision falls back to the **heuristic agent**, which accepts a trade that is strictly worth more
to it, so the result is not always "reject" as written; decide which is intended and fix text or
code; (c) an end-to-end check that a human sees an LLM-proposed trade (the trade-offer UI now
exists: `TradeOffers`).
