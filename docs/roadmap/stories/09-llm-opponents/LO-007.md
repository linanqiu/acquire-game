> **Why (owner decision 2026-11-14):** complete game transcripts are a first-class requirement for
> every game and every seat, are shown to users after a game ends, and are shared with the
> benchmark. A server-side-only, LLM-only log is no longer enough. Differences that matter:
> transcripts record human/bot decisions, engine events and public state too; the files are keyed
> by game id (`<game_id>.jsonl`), not room code; prompts and answers become public when the game
> ends (redacted while it runs) instead of never being exposed.
>
> **What exists:** `backend/agents/llm/decision_log.py`: per-agent ring buffer, one compact
> `llm` log line per decision (no prompts), and JSONL with full prompts to
> `<GAME_LLM_LOG_DIR>/decisions.jsonl` (one shared file, not `<room_code>.jsonl`; no rotation or size
> cap; no summary script). Retry prompts are not stored. Tests: `tests/test_llm_agent.py`
> (`test_decision_log_*`). The writer in AB-001 replaces the JSONL part; keep the compact log line.

## Context

When an LLM seat makes a bad move, or a game is slow, we need to see exactly what the model was
shown and what it said. This is also how cost and fallback rates are measured in production.

## Requirements

One record per decision, as a JSON line, containing: room code, game seq/turn, player id, seat
agent id and model, decision kind, prompt (system + user), raw response, parsed action,
validation error (if any), whether a repair call was made, whether fallback was used and why,
latency per call, tokens in/out, estimated cost, timestamp.

- Written to `logs/llm/<room_code>.jsonl` (path configurable); rotation/size cap.
- Prompts contain private hand info for the acting seat only, so these logs are **server-side
  only**: never sent to any client, never exposed over HTTP/WS.
- API keys and auth headers are never logged.
- A small CLI/script to summarise a log (fallback rate, latency percentiles, cost).
- Standard application log gets one summary line per decision (no prompt text).

## Acceptance Criteria

- [ ] One record per decision, including fallbacks and repairs.
- [ ] Test asserts no API key string appears in any record.
- [ ] Test asserts no endpoint returns log contents.
- [ ] Summary script output matches a hand-computed fixture log.
- [ ] Benchmark harness (LO-006) reuses the same record format for its metrics.

## Implementation Notes

- Suggested: `backend/agents/llm/trace.py`; call from `LLMAgent` after each decision.
