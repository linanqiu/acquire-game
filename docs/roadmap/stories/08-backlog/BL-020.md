# BL-020: Lighter and snappier: measured lag, condensed bot pacing, fewer messages, cheaper renders

## Metadata
- **Epic**: Backlog
- **Status**: `completed`
- **Priority**: `high`
- **Effort**: `L` (3+ hours)
- **Dependencies**: none

## Context

Owner feedback (2026-11-18, iPhone, playing against rules bots and LLM seats): "Generally it
should feel lighter weight and snappier, more responsive. Sometimes the lag is high."

Measure first, then fix the causes. Full numbers, method and recommendations:
[docs/architecture/performance.md](../../../architecture/performance.md).

## Findings (before)

- The wait between the human's turns was almost all deliberate pacing: 0.4 s after every agent
  action, about 3.3 actions per bot turn, so 4.0 s at a 3-bot table and 6.5 s with 5 bots, for
  2-5 ms of bot compute. LLM seats got the 0.4 s on top of each model call.
- Every bot move sent two identical-but-for-nothing `game_state` messages (the "thinking" state
  equals the state before it for a bot): 21 messages per 3-bot round.
- Server work is not a cause: 0.06 ms per action, 1.6 ms per bot decision, 0.4 ms per broadcast
  (calculator parts computed once per state), about 2.5 KB per state after deflate.
- Round trip to the deployed site: 106 ms from the sandbox (server 2 ms).
- On a 4x-throttled phone viewport: tap PLACE TILE -> tile shown about 300 ms (render of the
  pending state, then of the new state); each state re-rendered about 320 components, every board
  square; most main-thread time was style/layout/paint, with forced layouts in the table panel's
  measuring effect, the scroll reset, animation restarts and per-call number formatters.

## What changed

- **Pacing** (`seats.py`, `config.py`): a minimum gap between agent moves, counted from the first
  move so think time overlaps it: 0.1 s within a seat's turn (`agent_step_delay`), 0.35 s when the
  game moves to another seat (`agent_action_delay`). 3 bots: 4.0 s -> 1.4-1.7 s between my turns;
  5 bots: 6.5 s -> 2.9 s.
- **No identical state twice** (`broadcast.py`): per-recipient last-sent text; a new socket, the
  host on connect and the refresh route always get the state. Messages per 3-bot round 21 -> 10.
- **Placed tile shown at once** (`PlayerPage.tsx`): drawn on its square while the action is in
  flight; the next state draws it as it is, a refusal removes it. 300 ms -> 65 ms.
- **Store** (`gameStore.ts`): one update per `game_state`; unchanged parts (board, hotel, players,
  ruleset, hand, trades...) keep their identity.
- **Board** (`Board.tsx`, `Tile.tsx`): memoised board and squares with stable per-square
  handlers; the page passes memoised props and subscribes to the fields it reads.
- **Forced layouts** (`GameLayout.tsx`, `Tile.tsx`, `useChangeFlash.ts`, `lib/ruleset.ts`): measure
  only when the core parts change, read before write, write only changed values; scroll reset only
  when scrolled; reflow only to restart a running animation; one shared number formatter.
- **Code splitting** (`App.tsx`): host, games, transcript, bench and series pages load on first
  visit. Game JS 458 -> 401 KB, CSS 116 -> 84 KB.
- Test mode: `FAKE_LLM_DELAY` gives the fake LLM seat a think time (to see and test waiting on a
  slow seat).

Deviation from the suggestions: no diff protocol and no change to the calculator pack (the
numbers did not support them: 2.5 KB per state deflated, 0.4 ms per broadcast); the "thinking"
dots were kept (no measurable cost).

## Acceptance Criteria
- [x] Lag measured before and after, local and deployed (deployed read-only, 3 rules bots, no LLM
      seats), with the breakdown (network, server, pacing, rendering) written down in
      `docs/architecture/performance.md`.
- [x] Bot pacing condensed: each move still shown, a bot turn about 0.55 s; an agent's think time
      counts toward the pause.
- [x] No identical `game_state` sent twice to the same recipient; reconnects still get the state.
- [x] The human's own tile placement shows immediately and reconciles without a stale tile.
- [x] Fewer renders per state (board squares only when the board changes) and fewer forced
      layouts; rarely used pages code-split.
- [x] Same `apply_action` path for every seat; public/private information unchanged.
- [x] Guards: protocol tests (one state per move, no repeats, new socket gets state, pacing
      overlap and bound), a broadcast time budget for a 6-player game, store and board render
      tests.

## Status note
Railway was not changed. If `AGENT_ACTION_DELAY` is set on the service it now sets the pause
between seats (default 0.35 s); see the recommendations in the performance doc (region close to
the players, first-load chain).
