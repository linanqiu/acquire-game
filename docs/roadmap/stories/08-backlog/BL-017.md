# BL-017: Say each thing once; one compact line per chain when buying

## Metadata
- **Epic**: Backlog
- **Status**: `completed`
- **Priority**: `high`
- **Effort**: `L` (3+ hours)
- **Dependencies**: BL-014 (Board tab fits 390x675), BL-013 (phone UX pass), BL-011 (decision tab)

## Context

Owner feedback (2026-11-16): "Things like 'Your name' and 'Enter your name' are duplicated.
Other places too." And, on the buy view: tighten the rows, one compact row per chain.

The rule this story applies everywhere: **a fact the screen states is stated once**. Nothing
the player could read before is lost (every number stays on screen or one tap away), and every
control keeps its accessible name.

## Implementation Notes

- `lib/phaseText.ts`: `lobbyPhaseText`, `waitingPhaseText` (unit tested). `statusText` and the
  `waiting` prop of `DecisionTab` are gone; `waitingMessage` stays for the host page, which
  shows it only when the engine waits on someone other than the player on turn.
- `PageShell` `phaseLink`: the phase bar renders as a button (accessible name "PLACE A TILE. Go
  to Board"); the tab name and arrow are drawn from `data-go`, so the live region still
  announces the phase alone.
- `GameLayout`: `onTableVisible` tells the page whether the table panel is on screen (header
  numbers, phase link). A decision may mark parts with `data-table-core`; their summed height
  is `--core-need`, and while deciding the board yields up to 68% of the tab to it (BuyPanel
  only for now). The buy notes ("Can't afford any shares") moved into the footer next to the
  totals, so they never hide under it.
- `lib/playerName.ts`: `recallName` / `rememberName`.

## Deviations
- The brief suggested hiding the header numbers only where my row is visible. They are hidden
  on the whole Board tab (my row is always in the table panel, under a decision when there is
  one), so the header changes only when the tab does.
- The rows stay at 44px rather than shrinking further: the board yields instead.
