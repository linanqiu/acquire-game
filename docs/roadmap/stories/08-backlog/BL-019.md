## 0. The page is the one scroller

Before, the game page was a fixed frame (`position: fixed; height: 100dvh`) and every panel
scrolled inside it: the table panel under the board, the buy rows, the chat list, each tab body,
the wide sidebar, the merger decision (with a pinned "Cash after / CONFIRM" footer that content
slid under), the timeline of the transcript viewer. Now the document scrolls and only the parts
of the screen that must stay put are pinned.

| Scroll container or pinned element (before) | Decision |
|---|---|
| `PageShell .fill` (fixed, 100dvh, overflow hidden) | Removed: the shell is at least the screen high and the document scrolls. The header and phase bar are `position: sticky; top: 0` (kept: the phase bar is the way back to the decision) |
| `PageShell .main` (`overflow-y: auto`) | Removed |
| `#root` padding / max width around the game | Removed for the game (`:has(.fill)`), so the game is the screen |
| `GameLayout .table` (table panel, `overflow-y: auto`, size container) | Removed: as tall as its content. The Board tab is sized to the space between the pinned parts (`--chrome-top`, `--chrome-bottom`, measured); the board yields to the decision's core (`data-table-core`), and if it cannot fit, the page scrolls instead of the panel |
| `Tabs .panel` (every tab body, `overflow: auto`) | Removed: a long tab (Chains, Trades, Chat) scrolls the page |
| `DecisionTab .fill` (decision as tall as the panel, for a pinned footer) | Removed |
| `BuyPanel .footer`, `MergerDisposition .confirm` (`position: sticky` inside the panel) | Removed: the decision fits with the board, the button in the flow |
| Phone dock + tab bar | Kept, as one `position: sticky; bottom: 0` block (rack and tabs at the thumb), above the home indicator (safe-area inset) |
| Wide sidebar tabs (`flex` panel that scrolled) | Removed: the sidebar flows with the page; the board pane is `position: sticky` beside it, so the board stays in view |
| `GameLayout .pinned` (host TV cards, `overflow-y: auto`) | Removed |
| `ChatPanel .list` (`overflow-y: auto`, max 240px) | Removed: the messages are part of the page; in the Chat tab the input is pinned over the rack and tab bar, the tab opens at its foot, "New messages" when the reader scrolled up (now tested in the browser) |
| Transcript `VirtualList` (timeline, own scrollbar) | Removed: the timeline shows the decisions around the step, "All N decisions" opens the whole list in the page |
| Transcript seat table (`overflow-x: auto`, `min-width: 560px`) | Removed: the table fits 390 |
| Transcript replay controls (`position: sticky`) | Kept: one compact bar, the scrubber full width |
| `Modal` (trade sheet, `overflow-y: auto`) | Kept: a dialog over the page is a frame by nature (the sheet's rows scroll inside it) |
| `TextBlock` (LLM prompts, `overflow: auto`) | Kept: long prompts and raw JSON in a tool page; they are opened on purpose |
| Bench tables, game-over breakdown (`overflow-x: auto`) | Kept: wide data tables on wide-screen tool pages; they do not overflow at 390 in the screens checked |

Checked by `innerScrollers()` / `expectNoInnerScroll()` / `pageFrameProblems()`
(`screens/support/layout.ts`) on every game tab at 390x675 with touch and mobile emulation and
at 1366x768 (`screens/page-scroll.spec.ts`), in the Board-tab fit tests and in the transcript
journey. Tests whose premise was "the page never scrolls" now assert "no box scrolls inside the
page, the pinned parts are on screen and apart".

## 2. In-game header

A menu button (☰, 44px) takes the wordmark's place in a game (on wide screens the wordmark is its
label). It opens a small panel: the room code with **Invite** (the lobby's share), the theme
switch, **Rules in brief** (five lines from the ruleset in effect) and **Leave to the home page**
(the seat stays; Back returns to it). A tap outside or Escape closes it. Nothing in normal play
opens it; the header itself carries only what changes (bag, my numbers or the room code).

## 3. Transcript viewer

- **The scrubber jammed.** Each step was written to the address (`setSearchParams`, a
  `history.replaceState`) and the step was read back from the address. A finger drag across a
  216-step game wrote 175 times in 7 seconds; Safari refuses more than 100 history writes in 10
  seconds (a SecurityError), after which the step stopped following the thumb. The step now
  lives in the page and the address follows it at most every 400 ms, ending on the last step
  (the same drag: 17 writes). Measured per step (input to next frame, 216 steps, phone
  emulation): median 17-19 ms before and after; timeline rows are built once per transcript and
  the summary is memoised so neither grows with the step.
- **Title**: "Seat 2 won" (or "Game in progress"), one line of facts ("Nov 18 · 6 min · ended by
  declaration · 4 players"), badges only for the status, BENCH and a snapshot start; game id,
  room, start and end times, seed, prompt version, series and the download behind "Details".
- **Seats**: rank, the player on one line (name and icon), final money, moves; an AI seat's
  model, retries, fallbacks, tokens and cost on one quiet line under the name. Fits 390.
- **Replay controls**: one sticky bar of SVG icon buttons (no emoji glyphs; labels and titles
  kept), "Step 81 / 216", speed and copy-link, over a full-width scrubber.
- **Board and move together**: what happened in the step sits right under the board; then the
  decision panel, chains and players, the timeline window.

## 4. Host / watch page

The phase bar says what a player's page says ("BOB IS DISPOSING OF SHARES" instead of "Bob's
TURN - MERGER"); the lobby chat sits in the page's column with its margins. The table, chains and
log already use the players matrix and the merger log (BL-013/BL-017); the page scrolls like the
player's (no inner panels).

## 5. Light theme

Every main screen captured in light at 390x675. Found: the buy table's TILES and BANK headings
ran together ("TILESBANK", also in dark; columns 2px wider, no tracking); the menu's "Rules in
brief" kept a tap highlight. Contrast of borders, tints and the board read correctly in light.

## Left as it was, and why

- **Header numbers**: unchanged (the menu holds what does not change).
- **Host lobby**: a big-screen display; "PLAYERS (0/6)" and "Waiting..." stay (they read from
  across a room).
- **Transcript players list** (cards per player beside the replay board): long on a phone, but
  it is the replay's state; a matrix like the game's would be its own change.
- **Copy link to this step** has no browser test (the clipboard is not available headless).
