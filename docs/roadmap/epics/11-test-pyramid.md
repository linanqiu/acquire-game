# Epic 11: Test Pyramid

## Overview

Owner decision 2026-11-14. Replaces the strategy in [Epic 7](07-scenario-tests.md). Measured
problem: the Playwright scenario suite (62 tests, about 9,300 lines) did not finish in 10 minutes,
because each test plays 20-40 turns through the browser against live heuristic bots to reach the
screen it wants to check. The rules are re-verified through the browser over and over.

The previous rule "no database seeding in scenario tests" is **relaxed, with guard rails**. The
owner was burned before: tests that skipped the main (home) page looked good on coverage while
many real bugs sat in the paths they skipped. The guard rails below exist to prevent both failure
modes: slow tests that play whole games, and fast tests that never touch the real entry points.

## The four tiers

| Tier | What | Runs with | Starts from |
|------|------|-----------|-------------|
| 1. Engine | All rules. Property/fuzz full games through the decisions API. | `pytest backend/tests -q` | Python |
| 2. Protocol | Server driven in-process (no browser) with scripted seats: full games, reconnects, concurrency. | `pytest backend/tests -q` | HTTP/WS client |
| 3. Screen | Playwright on real servers, one screen state per test. | `npm run e2e:screens` | **Snapshot** loaded via test-mode endpoint, scripted opponents |
| 4. Journey | About 5-8 true end-to-end journeys, no shortcuts. | `npm run e2e:journeys` | **Always the home page** |

Rules are tested once, in tier 1. They are not re-verified through the browser.

### Guard rails

1. **Snapshot provenance.** Every tier-3 snapshot fixture is generated by real play: a recorded
   seed plus action list, replayed through the engine by a generator script. A backend test
   regenerates each fixture and compares it to the checked-in file. Hand-built snapshots are not
   allowed, so unreachable states cannot exist (TP-001).
2. **Journeys have no shortcuts.** Tier 4 always starts at the home page, uses only UI
   interactions, and never calls `/api/*` or test-mode endpoints. Required journeys:
   - create game -> lobby -> add AI/scripted seats -> play real turns -> merger -> trade ->
     game over -> play again;
   - multi-human (two browser contexts, join by room code);
   - human + LLM seat (fake provider);
   - host/spectator view;
   - reconnect/refresh mid-game;
   - error paths: bad room code, duplicate name, full room.
3. **Surface coverage map.** A checked-in table, [docs/tests/surface-coverage.md](../../tests/surface-coverage.md),
   lists every user-visible surface (every route/page, every home-page entry point, every game
   phase screen, every modal, every error state) against the journey or screen test that exercises
   it. A surface with no test is a visible gap. Coverage is measured in surfaces and journeys, not
   line or scenario counts (TP-006).

### Rules that stay

- Never hide bugs: a test that hits a stuck state fails; it does not return early.
- Screenshots as evidence at every step; console and page errors are checked.
- Determinism through seeding (`ACQUIRE_GAME_SEED`).
- Bots and humans use the same code paths.
- Detailed per-step logging.
- WebSocket for receiving state, HTTP for sending actions.

These are written out in `CLAUDE.md`, Testing section.
